Decision guide

Which package do you need?

Short answer: pick by what your users open. A browser or a printer — HTML Reporting. Microsoft Word — DOCX Reporting. Both share the same fluent mental model, and many teams ship both.

By requirement

You need… Html.Reporting Docx.Reporting
A printable, PDF-style page ✓ Best fitFixed pages; print/save to PDF from any browser —Word can print, but layout lives in Word's engine
An editable deliverable —Output is final-form HTML ✓ Best fitReal .docx users can revise and track changes in
Charts —Bring your own SVG via raw HTML ✓ NativeEditable Word charts: bar, line, pie, stacked
Barcodes (Code 128) ✓ Native PNGGenerated in-library ✓ Native vectorCrisp at any zoom and print resolution
Filling an existing branded template — ✓Placeholder & content-control replacement
Precise pagination control ✓Line-level splits, atomic row groups, layout warnings —Word paginates when the document opens
Document protection — ✓Restrict Editing with password verifier
Very large reports ✓Streaming, page-at-a-time async rendering ✓Open XML packages are compact
Zero dependencies ✓Dependency-free core ✓No Word, no COM — writes Open XML directly

The same mental model

Whichever you choose, the skills transfer: create a document, describe pages and content with fluent builders, publish. Here is the same header-content-footer shape in both:

TerraFluent.Html.Reporting

{% highlight csharp %} var report = ReportDocument.Create(PageSize.A4) .Header(h => h.AddText("Quarterly Report").Bold()) .Footer(f => f.AddPageNumber("Page {page} of {totalPages}")) .Content(c => { c.AddHeading("Executive Summary", HeadingLevel.H1); c.AddParagraph("Revenue improved across every practice."); }) .Build(); report.RenderHtmlDocument("report.html"); {% endhighlight %}

TerraFluent.Docx.Reporting

{% highlight csharp %} Document.Create(doc => { doc.Page(page => { page.Size(PageSize.A4); page.Header().Text("Quarterly Report", t => t.Bold()); page.Footer().Text(t => { t.Span("Page "); t.CurrentPageNumber(); t.Span(" of "); t.TotalPages(); }); page.Content().H1("Executive Summary"); page.Content().Text("Revenue improved across every practice."); }); }).PublishDocx("report.docx"); {% endhighlight %}

Honest counter-signals

  • Pick Docx.Reporting even for print if your organization's workflow reviews and signs documents in Word — fidelity to Word's own pagination matters more than pixel control.
  • Pick Html.Reporting even for "editable" asks if edits are really data changes — regenerate the report instead of letting people hand-edit output.
  • Need a true PDF file server-side (no browser in the loop)? Neither package produces PDF bytes directly; Html.Reporting gets you print-perfect pages you can convert with any HTML-to-PDF step you already trust.
  • Using both? They're independent packages with no shared dependency — adding both costs nothing but the two package references.
