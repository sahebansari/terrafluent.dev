Decision guide

Which package do you need?

Short answer: pick by what your users open. A final, portable file — PDF Reporting. A browser or an HTML pipeline — HTML Reporting. Microsoft Word — DOCX Reporting. All three share the same fluent mental model, and many teams ship more than one. Need a chart rather than a document? See Chart Reporting — its SVG output drops into any of the three below.

The same mental model

Whichever you choose, the skills transfer: create a document, describe pages and content with fluent builders, publish. Here is the same header-content-footer shape in all three:

TerraFluent.Pdf.Reporting

{% highlight csharp %} PdfDocument.Create(container => { container.Page(page => { page.Size(PageSize.A4); page.Header().Text("Quarterly Report").Bold(); page.Footer().AlignCenter().Text(t => { t.Span("Page "); t.CurrentPageNumber(); t.Span(" / "); t.TotalPages(); }); page.Content().Column(col => { col.Item().H1("Executive Summary"); col.Item().Text("Revenue improved across every practice."); }); }); }).PublishPdf("report.pdf"); {% endhighlight %}

TerraFluent.Html.Reporting

{% highlight csharp %} var report = ReportDocument.Create(PageSize.A4) .Header(h => h.AddText("Quarterly Report").Bold()) .Footer(f => f.AddPageNumber("Page {page} of {totalPages}")) .Content(c => { c.AddHeading("Executive Summary", HeadingLevel.H1); c.AddParagraph("Revenue improved across every practice."); }) .Build(); report.RenderHtmlDocument("report.html"); {% endhighlight %}

TerraFluent.Docx.Reporting

{% highlight csharp %} Document.Create(doc => { doc.Page(page => { page.Size(PageSize.A4); page.Header().Text("Quarterly Report", t => t.Bold()); page.Footer().Text(t => { t.Span("Page "); t.CurrentPageNumber(); t.Span(" of "); t.TotalPages(); }); page.Content().H1("Executive Summary"); page.Content().Text("Revenue improved across every practice."); }); }).PublishDocx("report.docx"); {% endhighlight %}

Honest counter-signals

  • Pick Html.Reporting even for PDF asks if your report must also live on a web page or in an email — one HTML output serves the browser, and printing covers the occasional PDF.
  • Pick Docx.Reporting even for print if your organization's workflow reviews and signs documents in Word — fidelity to Word's own pagination matters more than pixel control.
  • Pick Html.Reporting even for "editable" asks if edits are really data changes — regenerate the report instead of letting people hand-edit output.
  • Converting existing HTML to PDF? Pdf.Reporting is code-first, not an HTML-to-PDF converter — if your source content is already HTML, an HTML-to-PDF converter is a better fit.
  • Still on .NET Framework? Pdf.Reporting needs .NET 8+; Html.Reporting and Docx.Reporting run all the way back to .NET Framework 4.6.1 via netstandard2.0.
  • Using more than one? They're independent packages with no shared dependency — adding another costs nothing but the package reference.
